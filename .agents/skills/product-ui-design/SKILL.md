# 제품 UI 설계

특정 사용자가 목표를 완료할 수 있도록 제품 요구사항과 디자인 시스템을 실제 화면 구성으로 연결한다.

이 스킬을 직접 실행하면 독립적인 UI 명세 초안까지만 작성한다. 실제 제품에 적용하거나 기존 화면을 변경하는 작업은 `../product-design/SKILL.md`의 UI 부분 재실행으로 처리하여 UX 문구, 시스템 공백 판정, 접근성, 개발 인계와 영향도를 함께 확인한다.

## 참조

- `../../../references/planning-principles.md`
- `../../../references/design-principles.md`
- `../../../references/product-design-handoff.md`
- 관련 사용자 흐름, 정보 구조(IA), 화면 요구사항(화면 규칙 포함)
- 디자인 브리프, Foundation, 컴포넌트와 콘텐츠 가이드

## 작성 절차

1. 화면의 사용자 목표, 진입·종료 조건과 핵심 행동을 확인한다.
2. 정보 우선순위와 영역 구조를 먼저 정한다.
3. 기존 컴포넌트와 토큰을 연결한다.
4. 정상, 로딩, 빈 상태, 오류, 권한, 긴 콘텐츠와 반응형을 정의한다.
5. 포커스, 키보드, 중복 행동과 실패 후 복구를 연결한다.
6. 시스템에서 해결할 수 없는 항목을 `GAP-*`로 분리한다.

## 출력 형식

```markdown
# UI-{NN} {화면명} 제품 UI 명세

## 개요
| 항목 | 내용 |
| --- | --- |
| 사용자 목표 | ... |
| 진입·종료 | ... |
| 관련 기획 | F-*, SCR-*, SCR-*-R* |
| 적용 원칙 | DP-* |

## 정보 위계
## 영역과 레이아웃
| 영역 ID | 책임 | 콘텐츠 | 컴포넌트·Variant | 토큰 | 반응형 규칙 |
| --- | --- | --- | --- | --- | --- |

## 상호작용
## 상태와 예외
## UX 문구
## 접근성 요구
## 시스템 공백
| GAP ID | 요구 상황 | 기존 시스템 검토 | 제안 분류 | 영향 화면 | 상태 |
| --- | --- | --- | --- | --- | --- |
## 가정과 결정 필요
```

와이어프레임은 디자이너가 이 단계에서 그린다. 기획의 화면 요구사항 정의서(`screen-spec`)는 무엇이 필요하고 어떻게 동작하는지만 정하므로, 배치와 영역 구성은 여기서 결정한다.

문서 명세에 와이어프레임을 넣을 때는 공통 그림 규칙의 예외로 박스를 쓸 수 있다. 다만 한글 너비 때문에 테두리가 어긋나지 않도록 박스 안에는 영역 ID만 쓰고, 영역 설명은 `영역과 레이아웃` 표에 적는다.

```text
+------------------------------+
| A1                           |
+--------------------+---------+
| A2                 | A3      |
|                    |         |
+--------------------+---------+
| A4                           |
+------------------------------+
```

와이어프레임은 표의 조건, 결과와 상태를 대신하지 않는다. 이 출력은 UI 명세이며 Figma 화면이나 실제 시각 산출물이 아니다. 시각 UI 제작 요청에는 명세를 만든 뒤 `../visual-ui-production/SKILL.md`를 사용한다.

## 완료 기준

- 정보 위계와 Primary Action의 근거가 있다.
- 모든 요소가 기존 컴포넌트·토큰 또는 명시된 `GAP-*`와 연결된다.
- 모바일·데스크톱 등 요청된 화면 크기의 실제 재배치 규칙이 있다.
- 시각 명세만 작성했다면 실제 렌더링을 검증했다고 표현하지 않는다.
