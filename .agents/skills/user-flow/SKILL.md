# 사용자 흐름 설계

사용자가 목표를 달성하는 전체 경로를 화면 목록이 아니라 조건과 결과가 있는 흐름으로 작성한다.

## 참조

- `../../../references/planning-principles.md`
- `../../../references/service-context.md`
- `../../../references/glossary.md`
- 제품 브리프가 있으면 먼저 읽어 문제·사용자·범위를 유지한다.
- 정보 구조(IA)가 있으면 화면 ID, 진입 경로와 페이지별 접근 조건을 확인한다.

## 입력 확인

- 사용자의 목표와 역할
- 시작 지점과 완료 조건
- 필요한 정보·권한·선행 상태
- 연결할 기존 화면이나 기능
- 취소·실패 후 가능한 복구 방식

## 설계 절차

1. 흐름 하나당 사용자 목표를 하나 정한다.
2. 시작 조건과 성공 종료 조건을 먼저 적는다.
3. 최소 단계의 정상 흐름을 만든다.
4. 사용자 선택, 권한, 데이터 상태에 따른 분기를 추가한다.
5. 실패·취소·중단·재진입 시 복구 경로를 추가한다.
6. 각 단계에 흐름 ID와 필요 화면 ID를 연결한다. 화면 ID는 IA의 ID를 사용하고, IA에 없는 화면이 필요하면 `신규`로 표시해 IA 갱신 대상으로 남긴다. IA가 없으면 화면 ID를 임시로 부여하고 IA 작성 시 대조가 필요하다고 남긴다.
7. 규칙이 필요한 분기는 임의로 결정하지 않고 결정 필요로 남긴다. 확정된 규칙은 화면 정의서의 `화면 규칙`에 기록된다.
8. 표를 완성한 뒤 흐름도로 요약한다.

## 출력 형식

````markdown
# {목표} 유저 플로우 (사용자 흐름)

## 1. 흐름 개요

| 항목 | 내용 |
| --- | --- |
| 흐름 ID | F-01 |
| 사용자 | {역할} |
| 목표 | {완료하려는 일} |
| 시작점 | {진입 경로} |
| 선행 조건 | {로그인·권한·데이터 조건} |
| 성공 조건 | {관찰 가능한 완료 상태} |
| 중단 조건 | {진행할 수 없는 상태} |

## 2. 흐름도

```text
F-01 {목표} ─ 시작: {진입 경로}
│
▼
F-01-01 {단계} · SCR-01
│  └─ F-01-B01 {분기 조건} → F-01-03
▼
F-01-02 {단계} · SCR-02
│  └─ F-01-E01 {실패 조건} → 재시도 시 F-01-02
▼
F-01-03 {단계} · SCR-03
│
▼
완료: {성공 조건}
```

## 3. 정상 흐름

| 단계 | 현재 상태·화면 | 사용자 행동 | 시스템 결과 | 다음 단계 |
| --- | --- | --- | --- | --- |
| F-01-01 | ... | ... | ... | F-01-02 |

## 4. 분기 흐름

| 분기 ID | 발생 지점 | 조건 | 이동 경로 | 결과 |
| --- | --- | --- | --- | --- |
| F-01-B01 | F-01-02 | ... | ... | ... |

## 5. 실패·복구 흐름

| 예외 ID | 발생 조건 | 사용자에게 보이는 상태 | 가능한 행동 | 복구 결과 |
| --- | --- | --- | --- | --- |
| F-01-E01 | ... | ... | 재시도/취소/문의 | ... |

## 6. 필요한 화면

| 화면 ID | 화면명 | 역할 | 신규/기존 | 연결 단계 |
| --- | --- | --- | --- | --- |
| SCR-01 | ... | ... | ... | F-01-01 |

## 7. 결정 필요

- [ ] {결정 질문} — 영향 단계: {F-01-...}
````

흐름도는 `../../../references/planning-principles.md`의 그림 규칙을 따른다. 정상 흐름은 세로로 잇고, 분기·예외는 발생 단계 아래에 `└─`로 달며 이동 대상은 `→ 단계 ID`로 적는다. 흐름이 길면 흐름 ID 단위로 나눈다. 흐름도는 표의 조건과 결과를 대신하지 않는다.

## 필수 점검

- 로그인 만료, 권한 없음, 빈 데이터, 중복 제출, 네트워크 실패가 관련되는지 확인한다.
- 뒤로가기와 취소가 데이터에 미치는 영향을 적는다.
- 중단 후 재진입했을 때 처음부터 시작하는지 이어서 하는지 확인한다.
- 시스템 자동 처리와 사용자의 실제 행동을 같은 단계로 섞지 않는다.
- 흐름도의 단계·분기·예외 ID와 화면 ID가 표와 일치한다.
