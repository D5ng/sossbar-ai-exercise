# 소스바 용어 사전

작성일: 2026-10-05
최종 수정일: 2026-10-06

## 처음 읽는 사람을 위한 용어

| 용어 | 쉽게 말하면 |
| --- | --- |
| 프로젝트 | 팀의 협업 경험과 여러 회고를 담는 공간 |
| 방장 | 프로젝트를 운영하고 회고 차수·마감·완료를 관리하는 사람. 최초에는 프로젝트를 만든 사람 |
| 참가자 | 프로젝트 초대를 수락한 구성원. 실제 회고 작성 대상은 차수별 요청 시작 시 확정 |
| 회고 주기 | 매주·매월 등 팀이 정한 회고 간격 |
| 회고 차수 | 그 프로젝트의 한 번의 회고. 예: 1차 회고·2차 회고 |
| KPT | 유지할 것(Keep), 겪은 문제(Problem), 다음에 시도할 것(Try)으로 경험을 돌아보는 방식 |
| 팀이 선택한 Try | 팀이 논의해 실제 시도할 행동을 한 문장씩 남긴 기록. 개인 KPT의 제안과 구분 |
| 실행 결과 메모 | 다음 차수에서 이전 Try를 돌아보고 실행 결과·배운 점을 방장이 선택적으로 남긴 팀 내부 기록 |
| 개인 제출 / 팀 완료 | 개인 제출은 내 KPT를 보낸 상태, 팀 완료는 팀 논의 후 방장이 차수를 끝낸 상태 |
| 동료 피드백 | 특정 동료의 행동·도움이 된 사례·다음에 기대하는 행동을 남기는 선택 활동 |
| 직무 / 프로젝트 역할 | 직무는 프로필의 직업 분야, 역할은 해당 프로젝트에서 맡은 일의 짧은 설명 |
| BE / FE / PM / PD | 백엔드 개발 / 프론트엔드 개발 / 프로덕트 매니저 / 프로덕트 디자이너 |
| 자기 스타일 | 이번 차수에서 자신이 보인 행동 빈도를 본인이 응답한 기록. KPT 화면의 선택 항목 |
| 동료 스타일 집계 | 여러 동료의 관찰을 문항별 응답 비율로 보여주는 결과. 차수·문항별 서로 다른 동료 3명 이상 필요 |
| 결과 열람 자격 | 이번 차수의 공개 시점에 동료 한 명 이상에게 실제 제출한 조건. KPT 제출만으로는 생기지 않음 |
| 공개 가능 / 공개 완료 | 공개 가능은 조건을 충족한 상태, 공개 완료는 본인이 실제 외부에 게시한 상태 |
| 기본 공개 프로필 | 기본 정보가 외부에 보이는 프로필. 비공개 전환 가능하며 모든 받은 기록이 자동 공개되지는 않음 |
| MVP | 핵심 경험을 확인하기 위한 첫 출시 범위 |
| IA / 유저 플로우 / 화면 정의서 | 페이지 구조와 접근 조건 / 사용자의 행동 순서와 분기 / 화면별 정보·동작·규칙을 정리한 후속 설계 문서 |

## 문서 관리번호

관리번호는 사용자에게 입력하거나 외우도록 요구하는 서비스 용어가 아닙니다.

| 표시 | 뜻 |
| --- | --- |
| DEC | 제품 결정(Decision). 예: DEC-24는 24번 결정 |
| Q | 검토 질문(Question). 방향이 해결된 질문 번호도 남을 수 있음 |
| F | 사용자 흐름(Flow)의 단계 |
| U / P | 대상 사용자(User) / 해결하려는 문제(Problem) |
| G / NG | 목표(Goal) / 제외할 목표·범위(Non-goal) |
| AS / M | 검증할 가정(Assumption) / 확인할 지표(Metric) |
| CHK | 출시 점검 항목(Check) |
