# 서비스 기획 공통 원칙

모든 기획 스킬과 에이전트는 이 원칙을 따른다.

## 1. 문제와 해결책을 구분한다

- 문제는 사용자가 겪는 상황·행동·불편으로 표현한다.
- 기능 아이디어를 문제처럼 쓰지 않는다. `검색 기능이 없다`보다 `원하는 항목을 찾는 데 시간이 오래 걸린다`가 문제에 가깝다.
- 해결책을 정하기 전에 현재 대안과 문제의 중요도를 확인한다.

## 2. 정보의 상태를 표시한다

| 상태 | 의미 |
| --- | --- |
| 사실 | 사용자 자료나 확인된 근거가 있다 |
| 가정 | 아직 검증되지 않았지만 작업을 위해 임시로 둔다 |
| 결정 필요 | 선택에 따라 범위나 동작이 달라져 사용자의 판단이 필요하다 |
| 확정 | 사용자가 명시적으로 결정했다 |

사실과 가정을 섞지 않는다. 가정은 근거와 검증 방법을 함께 기록한다.

## 3. 추적 가능하게 작성한다

- 문서 항목에 식별자를 사용한다: 문제 `P-01`, 목표 `G-01`, 가정 `AS-01`, 흐름 `F-01`, 정책 `POL-01`, 화면 `SCR-01`, 인수 조건 `AC-01`, 이벤트 `EVT-01`.
- 리서치는 스터디 `RS-01`, 리서치 질문 `RQ-01`, 참가자 `PT-01`, 인사이트 `INS-01`, 과제 `T-01`, 사용성 문제 `UT-01`, 반영 제안 `REC-01`을 사용한다.
- 하위 산출물은 근거가 된 상위 식별자를 연결한다.
- 상위 요구사항이 바뀌면 연결된 정책·화면·인수 조건·이벤트를 다시 검토한다.

## 4. 사용자 관점과 시스템 동작을 함께 쓴다

- 사용자에게 보이는 상태와 시스템 내부 처리를 구분한다.
- 정상 흐름뿐 아니라 취소, 뒤로가기, 빈 상태, 권한 없음, 중복 요청, 실패 후 복구를 확인한다.
- 실행 주체, 발생 조건, 결과가 없는 문장은 완료된 요구사항으로 취급하지 않는다.

## 5. 범위를 통제한다

- MVP에는 핵심 문제를 해결하는 데 필요한 최소 기능만 포함한다.
- 좋은 아이디어라도 현재 목표와 연결되지 않으면 후속 후보로 분리한다.
- 사용자가 요청하지 않은 기능·정책·기술 구현을 임의로 확정하지 않는다.

## 6. 검증 가능한 표현을 사용한다

- `빠르게`, `적절히`, `직관적으로`처럼 판단 기준이 없는 표현은 수치·조건·관찰 가능한 결과로 바꾼다.
- 법률·보안·의료·결제처럼 위험이 큰 내용은 전문가 확인이 필요한 항목으로 표시한다.
- 시장 수치, 경쟁사 정보, 법적 의무는 출처 없이 사실로 단정하지 않는다.

## 7. 질문은 결정 단위로 묶는다

- 문서를 작성하는 데 꼭 필요한 정보부터 질문한다.
- 한 번에 과도한 질문을 던지지 않는다. 답변 가능한 범위로 초안을 만들고 미결정 사항을 남긴다.
- 질문마다 왜 필요한지와 어떤 항목에 영향을 주는지 적는다.

## 8. 복잡한 구조는 그림으로 요약한다

- 계층, 분기, 되돌아가는 경로처럼 표만으로 한눈에 읽기 어려운 구조는 아스키아트 그림을 함께 둔다. 단순한 순서 목록은 그림으로 만들지 않는다.
- 표가 원본이고 그림은 요약이다. 그림에만 있는 정보를 만들지 않고, 그림과 표가 다르면 표를 기준으로 그림을 고친다.
- 그림에도 식별자를 적어 표와 대조할 수 있게 한다.
- 그림은 `text` 코드 블록 안에 둔다.
- 한글은 고정폭 글꼴에서 영문보다 넓게 표시될 수 있으므로 다음을 지킨다.
  - 박스로 감싸지 않는다. 화살표, 트리, 들여쓰기로 표현한다.
  - 세로선과 연결선은 한글보다 왼쪽에 둔다. 한글 설명은 줄 끝에만 쓴다.
  - 멀리 되돌아가는 경로는 선을 그리지 않고 `→ 대상 ID`로 적는다.
- 사용할 문자: `│`, `─`, `├─`, `└─`, `┌`, `▶`, `▼`, `→`
- 한 그림이 한 화면에 들어오지 않으면 영역이나 흐름 단위로 나눈다.

좋은 예:

```text
F-01-01 로그인 · SCR-01
│  └─ F-01-E01 인증 실패 → F-01-01
▼
F-01-02 홈 · SCR-02
```

피할 예(한글 오른쪽의 테두리가 환경에 따라 어긋난다):

```text
┌────────┐
│ 로그인 │
└────────┘
```
