# 기획·디자인·개발 인계 계약

각 단계가 다음 단계에 무엇을 전달하며, 무엇을 임의로 결정할 수 없는지 정의한다.

## 식별자

| 영역 | 접두사 | 예시 |
| --- | --- | --- |
| 사용자·문제·목표 | `U`, `P`, `G` | `U-01`, `P-01`, `G-01` |
| 흐름·화면·화면 규칙 | `F`, `SCR`, `SCR-*-R` | `F-01`, `SCR-01`, `SCR-01-R01` |
| 화면 밖 접점 | `TP` | `TP-01` |
| 디자인 인계 점검 | `DHC` | `DHC-01` |
| 디자인 키워드·원칙 | `KW`, `DP` | `KW-01`, `DP-01` |
| 토큰·컴포넌트 | `TOK`, `CMP` | `TOK-01`, `CMP-01` |
| UI·문구 | `UI`, `COPY` | `UI-01`, `COPY-01` |
| 시스템 공백 | `GAP` | `GAP-01` |
| 인계·검토 | `HOF`, `DREV`, `A11Y` | `HOF-01`, `DREV-01`, `A11Y-01` |
| 가정·리서치 | `AS`, `RS`, `RQ`, `PT`, `INS`, `T`, `UT`, `REC` | `AS-01`, `INS-01`, `UT-01` |

## PM/PO에서 디자인으로

반드시 확인할 입력:

- 우선 사용자와 사용 환경, 문제와 제품 목표
- MVP 포함·제외 범위
- 정상·분기·실패·복구 흐름
- 정보 구조(IA): 페이지 계층, 내비게이션, 페이지별 접근 조건, 화면 밖 접점
- 역할과 권한(IA 접근 제어), 상태와 입력 규칙(화면 규칙 `SCR-*-R*`)
- 화면 목적, 핵심 행동, 요소 중요도, 데이터 양과 관찰 가능한 성공 조건
- 용어 사전(`planning/00-glossary.md`)과 확정·가정·결정 필요 상태

디자인은 미확정 규칙을 시각 요소나 문구로 확정하지 않는다. 규칙이 없더라도 안전한 초안은 만들 수 있지만, 영향을 받는 항목에 상태를 표시한다.

### 디자인 인계 점검

기획을 마치고 디자인을 시작하기 전에 확인한다. 기획 문서에서 오는 항목(`DHC-01`~`DHC-08`)은 문서로 판정하고, 기획서에 없는 항목(`DHC-09`~`DHC-13`)은 사용자에게 한 번에 묻는다. 판정은 `있음`, `부분`, `없음`, `해당 없음` 중 하나로 `design/00-design-context.md`의 `인계 점검`에 기록한다.

| ID | 항목 | 출처 | 없거나 부분일 때 |
| --- | --- | --- | --- |
| DHC-01 | 우선 사용자와 사용 환경(기기·장소·빈도·숙련도) | 서비스 기획서 `U-*` | 먼저 묻는다. 답이 없으면 가정으로 진행하고 디자인 브리프의 경험 목표를 모두 `가정`으로 표시한다. |
| DHC-02 | 문제, 목표, 성공 신호 | 서비스 기획서 `P-*`, `G-*`, `M-*` | 가정으로 진행하고 영향받는 키워드·원칙에 상태를 표시한다. |
| DHC-03 | 디자인 우선 흐름 | 서비스 기획서 MVP 범위, 유저 플로우 `F-*` | 먼저 묻는다. 어느 흐름부터 설계하느냐에 따라 우선 만들 컴포넌트가 달라진다. |
| DHC-04 | IA, 흐름, 화면 규칙 | 기획 문서 02~04 | 없는 부분은 가정으로 진행하고 영향 항목에 상태를 표시한다. |
| DHC-05 | 화면 요구사항: 핵심 행동, 요소 중요도, 상태, 데이터 양 | 화면 요구사항 정의서 | 중요도와 데이터 양이 없으면 기획에 보완을 요청한다. 디자이너가 임의로 정하지 않는다. |
| DHC-06 | 화면 밖 접점: 알림, 공유 미리보기 | IA `TP-*` | 화면만 설계 범위로 두고 알림·공유 미리보기는 범위 밖으로 기록한다. |
| DHC-07 | 용어 사전: 역할, 상태, 핵심 용어 | `planning/00-glossary.md` | UX Writer가 용어 후보를 만들고 `결정 필요`로 남긴다. |
| DHC-08 | 지원 환경: 기기, 반응형 범위, 접근성 수준, 테마 | 서비스 기획서 제약 조건(`CHK-NFR-01`, `CHK-NFR-05`, `CHK-NFR-07`) | 먼저 묻는다. Foundation의 범위가 바뀐다. |
| DHC-09 | 원하는 인상과 피할 인상 | 사용자 | 먼저 묻는다. 답이 없으면 키워드는 제품 근거로만 후보를 만들고 색상·서체를 확정하지 않는다. |
| DHC-10 | 기존 브랜드 자산: 로고, 브랜드 컬러, 서체와 사용 규정 | 사용자 | 먼저 묻는다. 자산이 없다고 확인되면 후보와 영향을 제시하고 결정을 받는다. |
| DHC-11 | 기존 디자인·코드 자산: 토큰, 컴포넌트, 아이콘·일러스트, 사용 중인 UI 라이브러리 | 사용자, 기존 저장소 | 확인되지 않으면 신규 구축을 `가정`으로 표시한다. |
| DHC-12 | 레퍼런스: 참고할 서비스·화면, 참고할 점과 따라 하지 않을 점 | 사용자 | 없어도 진행한다. |
| DHC-13 | 대표 샘플 데이터: 실제 예시 항목, 이미지, 수치 | 사용자가 제공하거나 승인한 자료 | 시안의 해당 영역을 `샘플 필요`로 표시하고 임의로 채우지 않는다. |

`먼저 묻는다`는 작업을 멈추라는 뜻이 아니다. 해당 항목에 영향을 받는 산출물을 확정하기 전에 사용자 답을 받거나 후보와 영향을 제시한다는 뜻이다.

## 디자인 시스템에서 제품 UI로

반드시 확인할 입력:

- 디자인 키워드와 행동 원칙
- Foundation과 의미 기반 토큰
- 컴포넌트의 목적, Anatomy, Variant, State와 사용 규칙
- 공통 콘텐츠, 접근성, 반응형과 모션 규칙
- 사용 중지 또는 교체 예정 항목

UI 설계자는 임의 토큰이나 공통 컴포넌트를 만들지 않는다. 시스템에서 해결할 수 없는 요구는 `GAP-*`로 반환한다.

## 제품 UI에서 개발로

개발 인계에는 다음을 포함한다.

- 화면별 정보 위계, 레이아웃과 반응형 규칙
- UI 명세 경로와 시각 UI가 있다면 `visual-index.md`, 디자인 파일·페이지·노드 식별자와 검증 상태
- 사용한 컴포넌트, Variant, State와 토큰 참조
- 사용자 행동에 따른 전환과 피드백
- 로딩, 빈 상태, 오류, 권한, 긴 콘텐츠와 중복 행동
- 최종 UX 문구와 접근성 요구사항
- 디자인 시스템 공백, 미결정 규칙과 구현 제외 범위
- 관련 화면 요구사항(`SCR-*` 요소·상태·규칙)과 확인 방법

개발 하네스는 디자인 인계만 보지 않고 관련 화면 요구사항 정의서를 함께 읽는다. 개발 기술 스택, API와 코드 구조는 개발 하네스가 추가된 뒤 별도 계약으로 확장한다.

## 시스템 공백 상태

| 상태 | 의미 | 다음 단계 |
| --- | --- | --- |
| 발견 | UI에서 기존 시스템으로 해결되지 않음 | 시스템 담당 분류 |
| 분류 완료 | 활용·확장·신규·화면 전용 중 판정됨 | 필요한 설계 반영 |
| 시스템 반영 | 토큰·컴포넌트 또는 화면 전용 규칙에 반영됨 | UI 재적용 |
| UI 재적용 | 실제 화면 명세 또는 시각 산출물에 반영됨 | 접근성·정합성 검증 |
| 검증 완료 | 관련 검토를 통과함 | 개발 인계 가능 |
| 보류·기각 | 현재 범위에 반영하지 않음 | 이유와 임시 처리 기록 |

미해결 Blocker/Major 공백이 있으면 인계 문서는 만들 수 있지만 준비 상태는 `Blocked`다. `Ready for Dev`는 관련 공백이 검증 완료됐거나 범위에서 명시적으로 제외된 경우에만 사용한다.

## 리서치에서 기획·디자인으로

리서치 결과는 원문을 직접 바꾸지 않고 반영 제안(`REC-*`)으로 전달한다. 사용자가 채택한 제안만 반영한다.

| 결과 | 전달 대상 | 반영 방식 |
| --- | --- | --- |
| 가정 판정, 인사이트 | 기획서 `AS-*`, `P-*` | `service-planning` 부분 재실행 |
| 사용성 문제 중 규칙·흐름·정보가 원인인 것 | IA, 유저 플로우, 화면 요구사항 정의서 | `service-planning` 부분 재실행 |
| 사용성 문제 중 배치·문구·컴포넌트가 원인인 것 | UI 명세, `COPY-*`, `GAP-*` | `product-design` 부분 재실행 |

사용자가 제공한 기록에 근거하지 않은 리서치 결과는 `사실`로 쓰지 않는다.
