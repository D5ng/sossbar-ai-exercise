# 디자인 개발 인계

개발자가 임의 해석해야 하는 부분을 줄이되 기술 구현 방법을 근거 없이 고정하지 않는다.

## 참조

- `../../../references/product-design-handoff.md`
- 관련 제품 정책, AC, 트래킹 플랜, Foundation, 컴포넌트, UI 명세, 시각 UI를 만들었다면 `visual-index.md`, 문구, 시스템 공백과 접근성 검토

## 출력 형식

```markdown
# {기능명} 디자인 개발 인계

## 준비 상태
- 상태: Ready for Dev / Blocked
- 미해결 Blocker·Major:

## 범위
| 항목 | 내용 |
| --- | --- |
| 관련 기획 | ... |
| 대상 화면 | ... |
| 제외 범위 | ... |

## 디자인 소스
| UI ID | UI 명세 경로 | Visual Index | 디자인 파일·페이지·노드 ID | 화면 크기·상태 | 시각 검증 상태 |
| --- | --- | --- | --- | --- | --- |

## 화면별 구현 계약
| HOF ID | UI 영역 | 컴포넌트·Variant | 토큰 | 상태·조건 | 행동·결과 | COPY | AC | EVT |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

## 반응형과 레이아웃
## 접근성
## 자산과 아이콘
## 시스템 공백과 임시 결정
## 미결정·개발 확인 필요
## 검증 체크리스트
```

## 작성 원칙

- 디자인 시스템과 다른 값을 별도 허용 없이 만들지 않는다.
- 요청 시작과 성공을 구분하고, 실패·취소·재시도 상태를 포함한다.
- 실제 API, 프레임워크와 코드 구조가 없으면 구현 방식을 확정하지 않는다.
- 디자인 링크만 남기지 않고 상태와 조건을 텍스트 계약으로 기록한다.
- 미해결 Blocker/Major `GAP-*`가 있으면 인계 문서를 `Blocked`로 표시한다.
- 시각 UI를 만들었다면 `visual-index.md`와 실제 파일·노드 식별자를 연결한다. 시각 산출물이 없는 경우 `해당 없음`과 그 이유를 적는다.

## 완료 기준

- 모든 화면 영역이 컴포넌트, 토큰 또는 `GAP-*`와 연결된다.
- 개발과 QA가 상태별 결과를 판정할 수 있다.
- 미확정 제품 정책과 기술 결정이 명시돼 있다.
- 사용자 행동과 처리 결과에 필요한 `EVT-*`가 연결되거나 해당 없음이 명시돼 있다.
- 개발자가 UI 명세와 실제 시각 원본을 다시 열 수 있거나 시각 산출물이 없다는 사실이 명확하다.
