# 시각 UI 제작과 검증

문서 명세를 실제 편집 가능한 디자인 산출물로 옮기고, 요청한 화면 크기와 주요 상태가 의도대로 보이는지 확인한다.

## 참조

- `../../../references/design-principles.md`
- 관련 UI 명세, Foundation, 컴포넌트, UX 문구와 접근성 요구
- 사용하는 디자인 도구의 공식 스킬과 작성 규칙

Figma를 사용할 때는 실행 환경에 제공된 Figma 작성 스킬을 먼저 읽고 그 도구로 작업한다. 디자인 도구에 접근할 수 없으면 이미지나 링크를 만든 것처럼 가장하지 말고 UI 명세까지만 완료됐다고 보고한다.

`frontend-design` 같은 외부 디자인 스킬은 시각 방향과 타이포그래피 판단에만 참고한다. 무엇을 만들지는 UI 명세가 정하며, 충돌하면 이 하네스가 우선한다. 시각적 완성도를 위해서라도 승인되지 않은 문구, 수치, 이미지를 채우지 않는다.

## 작성 절차

1. 대상 디자인 파일, 페이지, 프레임과 화면 크기를 확인한다.
2. 기존 컴포넌트와 변수 라이브러리를 재사용한다.
3. 정보 위계, 레이아웃, 최종 UX 문구와 핵심 상태를 실제 프레임으로 만든다.
4. 시스템에 없는 요소는 로컬 공통 컴포넌트로 숨기지 않고 `GAP-*`로 기록한다.
5. 최소한 기본, 로딩·빈 상태·오류 중 관련 상태와 요청된 반응형 화면을 시각 확인한다.
6. 결과 링크, 파일·페이지·노드 식별자와 검증 범위를 `visual-index.md`에 기록한다.

## 출력 인덱스

```markdown
# {기능명} 시각 UI 인덱스

| UI ID | 화면·상태 | 디자인 파일 | 페이지·노드 ID | 화면 크기 | 시스템 사용 | 검증 상태 |
| --- | --- | --- | --- | --- | --- | --- |

## 시각 QA
- 정보 위계와 잘림·겹침
- 반응형 재배치
- 긴 콘텐츠
- 포커스·오류·상태 표현
- 디자인 시스템 공백

## 검증하지 못한 범위
```

## 완료 기준

- 실제 디자인 산출물의 위치와 노드 식별자를 다시 열 수 있다.
- 요청된 화면 크기와 주요 상태를 실제로 확인했다.
- 문서 명세와 시각 결과의 차이를 기록했다.
- 정적 이미지만으로 상호작용이나 접근성 완료를 주장하지 않는다.
